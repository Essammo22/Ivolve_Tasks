# Lab 14: StatefulSet with Headless Service

This lab deploys a single-replica MySQL database as a **StatefulSet** in the `ivolve` namespace, exposed through a **Headless Service**, with persistent storage, scheduling rules, and configuration injected from a ConfigMap and a Secret.

## Requirements

- Create the `ivolvedb` StatefulSet in the `ivolve` namespace with 1 replica running MySQL.
- Consume environment variables from a ConfigMap and a Secret.
- Add a node selector so the Pod runs on the node labeled `project=ivolve`.
- Add a toleration for `workload=ivolveApp` with effect `NoSchedule`.
- Use a PVC template to mount `/var/lib/mysql`.
- Create a headless Service named `ivolvedbsvc` targeting the MySQL Pod.
- Confirm the database is operational with a MySQL client.
- Verify the Pod's DNS resolution inside the cluster.

> Kubernetes resource names must be lowercase, so `ivolveDB` and `ivolveDBSvc` are written as `ivolvedb` and `ivolvedbsvc`.

## Project structure

```
.
├── configmap.yaml
├── secret.yaml
```

## Manifests

### `configmap.yaml`

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: ivolvecm
  namespace: ivolve
data:
  DB_HOST: db
  DB_USER: ivolve_user
```

### `secret.yaml`

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: ivolvesecret
  namespace: ivolve
data:
  DB_PASSWORD: <base64-encoded-user-password>
  MYSQL_ROOT_PASSWORD: <base64-encoded-root-password>
```

> Values under `data:` must be base64-encoded. Generate them with `echo -n 'your-password' | base64`. Base64 is encoding, not encryption, so never commit real passwords to a public repository.

### `pv.yaml`

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: ivolvedbpv
spec:
  capacity:
    storage: 1Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  hostPath:
    path: /mnt/mysql-data
  volumeMode: Filesystem
```

> The cluster has no dynamic provisioner or default StorageClass, so a PV is created manually. The PVC generated by the StatefulSet template binds to it because both use no StorageClass and the size and access mode match.

### `service.yaml` (Headless Service)

```yaml
apiVersion: v1
kind: Service
metadata:
  name: ivolvedbsvc
  namespace: ivolve
  labels:
    app: ivolvedb
spec:
  clusterIP: None
  ports:
    - port: 3306
      name: mysql
  selector:
    app: ivolvedb
```

### `statefulset.yaml`

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: ivolvedb
  namespace: ivolve
spec:
  serviceName: ivolvedbsvc
  replicas: 1
  selector:
    matchLabels:
      app: ivolvedb
  template:
    metadata:
      labels:
        app: ivolvedb
    spec:
      nodeSelector:
        project: ivolve
      tolerations:
        - key: workload
          operator: Equal
          value: ivolveApp
          effect: NoSchedule
      containers:
        - name: mysql
          image: mysql:latest
          ports:
            - containerPort: 3306
              name: mysql
          env:
            - name: MYSQL_ROOT_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: ivolvesecret
                  key: MYSQL_ROOT_PASSWORD
            - name: MYSQL_USER
              valueFrom:
                configMapKeyRef:
                  name: ivolvecm
                  key: DB_USER
            - name: MYSQL_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: ivolvesecret
                  key: DB_PASSWORD
            - name: MYSQL_DATABASE
              value: ivolve
          volumeMounts:
            - name: mysql-data
              mountPath: /var/lib/mysql
  volumeClaimTemplates:
    - metadata:
        name: mysql-data
      spec:
        accessModes:
          - ReadWriteOnce
        resources:
          requests:
            storage: 1Gi
```

## Deployment steps

```bash
kubectl create namespace ivolve

kubectl label node worker1 project=ivolve

kubectl apply -f configmap.yaml
kubectl apply -f secret.yaml
kubectl apply -f pv.yaml
kubectl apply -f service.yaml
kubectl apply -f statefulset.yaml
```

The ConfigMap and Secret must exist before the StatefulSet, otherwise the Pod fails to start.

### DNS resolution

A temporary Pod is created inside the namespace to run the lookup:

```bash
kubectl run network -n ivolve \
  --image=busybox:1.36 \
  --restart=Never \
  --overrides='{"spec":{"tolerations":[{"key":"workload","operator":"Equal","value":"ivolveApp","effect":"NoSchedule"}]}}' \
  -- sleep 3600
```

```bash
kubectl get pods -n ivolve -o wide
```


The resolved address `192.168.235.194` matches the IP of `ivolvedb-0`, so the Pod's stable DNS name works through the headless Service.

## Key concepts

- **StatefulSet** gives each Pod a stable name (`ivolvedb-0`) and its own PVC that survives Pod restarts.
- **Headless Service** (`clusterIP: None`) does not load-balance. It returns Pod IPs directly and gives each Pod a stable DNS name: `<pod>.<service>.<namespace>.svc.cluster.local`.
- **`serviceName`** in the StatefulSet must match the headless Service name.
- **nodeSelector** restricts scheduling to nodes with a matching label, while a **toleration** only allows scheduling on nodes with a matching taint and does not force it.
- **volumeClaimTemplates** create one PVC per Pod automatically.

## Cleanup

```bash
kubectl delete -f statefulset.yaml -f service.yaml -f secret.yaml -f configmap.yaml
kubectl delete pod network -n ivolve
kubectl delete pvc mysql-data-ivolvedb-0 -n ivolve
kubectl delete -f pv.yaml
```

The PVC is not deleted with the StatefulSet, so it must be removed manually. Because the PV uses the `Retain` policy, the data stays in `/mnt/mysql-data` on the node until it is removed manually.
